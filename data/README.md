# カクテルマスター

`raw/`にはカクテルデータの取得元からコピーした6つのCSVを保存しています。アプリはこのプロジェクト内のコピーを取り込み元として使い、元ディレクトリに実行時依存しません。

`source-manifest.json`は現在のCSVの件数とSHA-256です。画像URLの更新前のハッシュは `original_sha256` として保持します。CSVとこの記録はGit管理します。

## 正規化方針

取り込み処理で空欄kind_idをnullにし、検索用文字列をNFKC正規化、度数を数値と原表記に分けます。IDと外部キーの対応、表示名、分量の原表記は保持します。kind_idによる代用グループは勝手に変更しません。

コピーしたCSVの画像URLは、取得確認済みの新しい配信先へ更新しています。その他の列はコピー時の値を維持します。正規化処理は `server/import.ts` に実装し、取り込み時にSQLiteへ反映します。度数は数値だけでなく「8度以下」などの範囲も保持し、不明と0%を区別します。生成DBや注文・在庫などの運用データはGit管理しません。

## 画像URLの更新

WSLのターミナルでプロジェクトのルートから実行します。

```bash
./scripts/npm.sh run data:update-images
./scripts/npm.sh run data:import
```

新しい配信先の600px画像を、元のファイル名→末尾に`_01`追加→`-01_01`形式などの順で試します。HTTP成功・画像Content-Type・画像のバイナリ形式を確認できたURLだけを書き換えます。画像ファイル自体は保存しません。

取得できない行は元のURLを維持します。権限エラーやネットワークエラーではその行の追加候補を試さず、429を受けたら新たな確認を停止します。並列数は3です。

`image-url-update-report.json`には全行の結果、試したURL、HTTPステータス、更新件数を記録します。再取り込みでは、注文履歴の画像が旧マスターと一致する場合に配信URLだけを更新します。注文名・材料・分量などの記録は保持します。
