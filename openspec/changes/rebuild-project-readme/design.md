## Context

現行構成はReact/Vite、Pages Functions、API Worker、D1、Firebase認証。起動・配備の詳細はdocs/DEPLOYMENT.mdにあり、旧LAN用コマンドもpackage.jsonに残っている。本体LICENSEは存在せず、フォントのライセンスのみ同梱されている。

## Goals / Non-Goals

初見の利用者と開発者が、用途を理解し、必要な認証設定を揃えてローカル起動できるREADMEにする。アプリ改修、公開配備、ライセンス選定、第三者素材の許諾取得は対象外。

## Decisions

### 項目と掲載理由

| 項目                   | 読者が判断・実行できること                                   |
| ---------------------- | ------------------------------------------------------------ |
| 概要・主な機能         | 誰の何を解決するアプリか、自分の用途に合うか                 |
| 利用フロー・制約       | 家主と客人の操作、在庫と注文の扱い                           |
| アーキテクチャ         | 認証・API・保存先の責務とローカルとの差                      |
| クイックスタート       | 前提環境、取得、依存導入、DB初期化、両側の認証設定、起動確認 |
| 開発・検証             | 日常コマンド、CIとの対応、OpenSpecでの変更手順               |
| デプロイ・運用         | 詳細手順への入口、mainマージ時の自動配備                     |
| ディレクトリ・データ   | 変更箇所、CSVからD1への反映、画像の扱い                      |
| トラブルシューティング | 初回設定で起きやすい問題の切り分け                           |
| コントリビューション   | Issue・PRに必要な情報と確認事項                              |
| ライセンス             | 本体と第三者素材の権利状態                                   |

日本語を基本とし、目次・表・テキスト構成図で読み飛ばせる構成にする。全面英訳や操作画面の追加は今回行わず、現在のUI・仕様と一致した説明を優先する。

ローカル起動はREADME内で完結させる。クラウド設定・復旧の全文転載は更新箇所が増えるため避け、運用資料へリンクする。未検証の公開URL、画像、ライセンスバッジは追加しない。

文書変更に架空の機能仕様を作らず、OpenSpec CLIが提供するskip_specsを利用する。changeはPRレビュー用に保持し、アーカイブはマージ後の運用に委ねる。

## Risks / Trade-offs

- [既存資料の旧LAN手順との混同] → 現行クラウド版のコマンドを列挙し、旧資料は履歴と明記する。
- [認証・運用環境による差] → Firebase実設定が必要な範囲と、認証情報なしで実行できる自動検証を区別する。
- [OSS公開可能との誤認] → LICENSE未設定とCSV・画像の権利確認未完了を明示する。

## 検証方針

READMEのリンク先、目次、npmコマンド、設定名を実ファイルと照合する。ローカルD1初期化とAPI起動、テスト・ビルド・整形・OpenSpec strict検証を行う。Firebase実ログインとクラウド配備は実施対象外と記録する。
