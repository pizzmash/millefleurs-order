## ADDED Requirements

### Requirement: 共通確認ダイアログ
システムは招待リンク再発行と注文数リセットに、見出し・影響・補足・キャンセル・実行ボタンを備えた共通意匠のモーダル確認を表示すること（SHALL）。

#### Scenario: 注文数のリセットを確認する
- **WHEN** 家主が「注文数をリセット」を選ぶ
- **THEN** 全カクテルの注文数が0になること、元に戻せないこと、注文履歴・受付中の注文が残ることを確認できる。

#### Scenario: 招待の再発行を確認する
- **WHEN** 家主が「招待リンクを再発行」を選ぶ
- **THEN** 以前のリンク・QRが使えなくなること、参加中の客人には新しいリンクで再参加が必要になること、注文履歴が残ることを確認できる。

### Requirement: 操作に隣接した補足
システムは「リセット後は0から集計します」を注文数リセットボタンと同じ領域に常時表示すること（SHALL）。

#### Scenario: 注文数を表示する
- **WHEN** 家主が注文数タブを開く
- **THEN** 集計見出しには受付成立杯数の説明のみを表示し、リセット後の説明はリセット操作の近くで読める。

### Requirement: 確認操作のアクセシビリティと非同期状態
システムは確認中の背景操作を抑止し、キーボードで安全に中止・確定できること（SHALL）。実行中は二重操作と中止を無効にし、失敗はダイアログ内に表示すること（SHALL）。

#### Scenario: 確認を中止する
- **WHEN** 家主が確認を開き、キャンセルまたはEscapeを選ぶ
- **THEN** 初期フォーカスはキャンセルにあり、APIを実行せず閉じ、起点ボタンへフォーカスが戻る。

#### Scenario: 通信中と失敗
- **WHEN** 家主が操作を確定する
- **THEN** 実行中ラベルを表示し、完了まで中止と再実行を抑止する。成功時は更新結果を表示して閉じ、失敗時はエラーを確認して明示的な再実行か中止を選べる。

#### Scenario: 狭い画面
- **WHEN** 320px幅の画面で確認を開く
- **THEN** 横にはみ出さず説明と48px以上の操作ボタンを表示する。
