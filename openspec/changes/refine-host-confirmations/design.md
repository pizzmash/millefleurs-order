## Context
既存UIは暗い背景とゴールドを基調とする。対象操作はいずれも確定前に影響の理解が必要だが、現状はインラインでボタンを置換している。

## Goals / Non-Goals
操作の影響を読みやすくし、通常画面の情報階層と2操作の一貫性を改善する。APIや集計方法の変更は対象外。

## Decisions
- インライン展開は視線とレイアウトが動き、ブラウザー標準confirmは既存意匠・非同期状態を表現できないため、共通のHTML dialogを採用する。
- ダイアログは画面中央、最大幅440px。暗い半透明背景・既存パネル色・控えめな警告色を使う。見出し、操作の影響、補足、キャンセル／明示的な実行ラベルの順に配置する。
- 通常の管理操作は区切り線と枠線ボタンでまとめる。リセット後の補足はボタンと同じ領域に常時表示する。
- showModalによる背景の操作抑止とフォーカス制御を利用し、初期フォーカスはキャンセル、終了後は起点へ戻す。Escapeで中止できるが、通信中は中止・再実行を無効にする。背景クリックでは閉じない。
- 失敗時はダイアログ内でエラーを表示し、明示的な再実行かキャンセルを選べる。自動再送しない。リセット後は成功・失敗とも集計を再取得する。
- スマートフォンでもボタンを48px以上とし、狭い幅では縦積みにする。低い画面ではダイアログ内をスクロール可能にする。

## Risks / Trade-offs
ネイティブdialogの利用により古いブラウザーは対象外。現行のChromiumでキャンセル・Escape・フォーカス・通信中・失敗・成功・画面幅を確認する。
