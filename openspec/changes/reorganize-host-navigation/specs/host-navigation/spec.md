## ADDED Requirements
### Requirement: 家主のカクテル閲覧
システムは家主に全カクテルの一覧と詳細を提供しなければならない（SHALL）。作成可能を第一、バー別注文数降順を第二に並べ、同数は名前・ID順とする。検索・絞り込み・ページ送りを提供し、注文操作は表示しない。
#### Scenario: 不足のあるカクテルを見る
- **WHEN** 家主が不足材料のあるカクテルを選ぶ
- **THEN** 一覧では材料名を表示せず、カード右下に丸付きチェック（代用を含め作成可能）または丸付き×（材料不足）だけを表示する。状態の文字は表示せず、アイコンに読み上げ名とツールチップを付ける。詳細では所持にチェック、代用可能に交換矢印、不足に×のアイコンを添え、代用候補だけを補足する。色の凡例と各材料の状態文は省き、アイコンには読み上げ用の状態名を付ける。注文ボタンはない
#### Scenario: 人気より作成可否を優先する
- **WHEN** 作成不可のカクテルの注文数が作成可能なものより多い
- **THEN** 作成可能なカクテルを先に表示し、並び順を確定してからページ分割する
### Requirement: 設定の階層化
システムは設定一覧からバー名、注文受付・招待リンク、注文数・リセット、アカウントに遷移できなければならない（SHALL）。個別ページ左上の矢印は設定一覧に戻る。注文内の注文数項目とアカウントの下部タブを廃止する。
#### Scenario: 招待の管理
- **WHEN** 家主が設定の注文受付・招待リンクを開く
- **THEN** 受付の切替と確認を伴うリンク再発行ができ、お迎えにはQR・URL共有が残る
### Requirement: 初回バー名設定
システムは新規家主の初回ログイン時にバー名を入力させ、保存成功を永続化しなければならない（SHALL）。既存家主には再入力させない。
#### Scenario: 保存後の再ログイン
- **WHEN** 家主がバー名を保存してから再ログインする
- **THEN** 初回設定画面を表示せず通常画面を開く
#### Scenario: 未完了の再開
- **WHEN** 新規家主が名前を保存せず離脱する
- **THEN** 次のログインで名前設定を再表示する
### Requirement: 読み取りの抑制
システムはバー別在庫と累計の索引を利用し、不変カタログを再利用しなければならない（SHALL）。新規一覧・詳細は定期ポーリングと注文履歴の全件集計を行わない。
#### Scenario: 一覧の再取得
- **WHEN** 同一カタログversionの一覧を再取得する
- **THEN** カタログの全件読み取りを省き、当該バーの在庫と累計から結果を生成する
