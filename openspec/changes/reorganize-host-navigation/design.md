## Context
家主画面は注文・在庫・お迎え・アカウント。客人の一覧・詳細と在庫判定は共用可能。D1の無料枠を考慮する。

## Goals / Non-Goals
全カクテル確認、設定集約、初回命名を実現する。客人の注文仕様や集計方式は変更しない。

## Decisions
- 下部は注文・カクテル・在庫・お迎え・設定。設定はバーの名前／注文受付・招待リンク／注文数／アカウントの4項目。受付とリンクは客人の参加管理としてまとめ、QR表示と共有はお迎えに残す。個別ページの左上矢印で設定一覧へ戻る。
- 客人コンポーネントを家主モードでも使用。全カクテルを作成可能降順→注文数降順→日本語名→IDでページ分割前に並べる。一覧は写真・名前・技法・度数と作成可否だけに絞り、材料名は出さない。家主カード右下の遷移矢印を丸付きチェック／×に置き換え、度数と同じ行に揃える。状態文は表示せず、読み上げ名とツールチップで補足する。代用可能もチェックに含める。材料不足のカードも通常どおり詳細を開ける。詳細は材料の左にチェック（所持）・交換矢印（代用）・×（不足）を揃え、代用候補だけを補足する。凡例は設けず、状態色と読み上げ可能なアイコンを併用する。
- 一覧は既存の不変カタログキャッシュ、在庫と累計のbar_id主キー範囲検索を使用。orders集計・材料ごとのSQL・新規定期ポーリングを追加しない。詳細は既存の単一レシピ取得を使い累計も取得しない。
- bars.name_configuredを追加。既存行は完了扱い、新規bootstrapは明示的に0を保存。名前のPATCH成功時だけ1にし、端末・セッションが変わっても再表示しない。途中離脱や失敗時は再開する。
- 旧/host/accountは設定のアカウントとして表示する。

## Risks / Trade-offs
Worker更新前に0003の適用が必要。カタログはWorkerのコールドスタート時のみ全件読み取りが生じ、以後同じversionでは再利用する。並び替えは検索条件やページ変更時に最新状態を反映する。

## ローカル動作確認での修正
一部の埋め込みブラウザーがOriginを省略するため、変更APIにX-Millefleurs-Originを送信する。APP_ENV=localかつOriginが欠落した場合に限り、PUBLIC_APP_URLのoriginと照合する。明示的な別Origin・文字列null・本番では代替を認めない。別サイトからのカスタムヘッダー付きリクエストはCORS preflightを許可しない。未ログインの/hostと/は同じ案内を表示するので「サービス案内へ」を削除する。

- 新規bootstrapではaccepting_orders=1を明示する。既存行の一括変更やログイン時の再設定は行わず、家主が停止した状態を維持する。追加SQLやマイグレーションは不要。初回命名画面で受付中から始まることと設定から停止できることを伝える。
