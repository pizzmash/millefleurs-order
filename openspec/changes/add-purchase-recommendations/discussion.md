# 購入によるカクテル拡張の相談

## ユーザーの要望（2026-09-07）

- 未所持材料を購入すると、作成可能なカクテルがどれだけ増えるか知りたい。
- 購入する材料の組み合わせについて、増えるカクテル数を最大化したい。
- 購入種類数a、指定方法、画面構成は未決定。相談からOpenSpecによる仕様化・実装まで依頼。

## 既存仕様の確認

- 在庫は材料ごとの「ある／ない」。残量・価格は管理していない。
- 有効なkind_idが同じ材料は代用可能。kind_idがnullの別材料同士は代用しない。
- 水・氷は常備品。レシピの全材料が揃う必要がある。空レシピは作成可能にしない。
- 在庫画面 /host/inventory に「ある材料」「作れるカクテル」の集計がある。

## 初回提案（追加相談により下記のとおり更新）

- 在庫画面の集計下に「買い足しで増やす」を設け、そこから詳細な購入提案を開く。
- 初期版は購入種類数の上限を1〜5で家主が選択。初期値は3。
- aは「ちょうどa種類」ではなく「最大a種類」。同じ増加数なら購入種類数が少ない組み合わせを優先。
- 最も多く増える購入セットを1件表示。購入材料、現在の作成可能数、増加数、購入後の合計、新たに作れるカクテル一覧を示す。
- 同じkind_idの材料は購入効果が同じためまとめ、購入できる具体的な材料名も表示する。既に在庫・常備品で満たす種類は購入候補から除外。
- 数値はセット全体の効果であり、材料ごとの増加数の単純加算にしない。
- 提案の閲覧・計算は在庫を変更しない。
- 価格・味の好み・購入先は初期版の最適化対象に含めない。

## 最適化と性能の論点

各カクテルについて、現在不足する材料の代用グループ集合Mを求める。購入グループ集合Sについて、1 <= |M|かつMがSの部分集合になるカクテルの件数を、|S| <= aの下で最大化する。カクテルIDごとに1件として数える。

1品だけでは増えない材料同士の相乗効果があるため、単品効果順の選択では最大値を保証できない。厳密探索の枝刈り・候補圧縮を検討し、実データと在庫条件別の計測で対応範囲を決める。1〜5での十分な応答速度は未検証。10種類への拡張は性能確認後に判断する。近似計算へ切り替える場合は別途仕様判断を行い、最大値を保証しない結果を「最適」と表示しない。

## 初回の相談事項（下記の追加相談で対応方針を決定）

- 初期版の購入上限を1〜5・初期値3とするか、最初から10まで必要か。
- 最大値の保証を優先するか、より広い購入数への対応・応答速度のため近似を許容するか。

合意後にproposal.md、specs/、design.md、tasks.mdを作成し、仕様検証、実装、最適性と既存在庫判定の整合性に関するテスト、ビルドを行う。

## 追加相談と採用判断（2026-09-07）

ユーザー: 10種類もできると嬉しい。計算量的に難しければ1〜5でよく、その場合の初期値は5を希望。

実データの試作で10種類の厳密計算が空在庫約4.8秒、頻出5グループ所持約2.6秒で完了。ランダムな在庫も8条件を検証し8秒以内に完了した。これに基づき1〜10種類に対応し、初期値5を設計判断として採用する。画面構成と最大a種類という扱いは前回提案に基づく設計判断。
